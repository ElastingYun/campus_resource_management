## 1. 本次任务与责任边界

- 业务目标：交付申请、多级审批、驳回、超时扫描、认证/RBAC、审计及 M1 适配代码，补齐数据库测试和接入说明。
- 本轮验收：正常、失败、边界和并发有真实测试；文档区分本地实现、契约测试和未完成的真实外部联调。
- 修改 C 自有目录、对应测试和 C 自有版本化 SQL，不创建全局后端工程、不修改其他成员模块或部署配置。
- 通过可挂载 FastAPI 组件和显式配置接入统一工程；当前直接使用 PostgreSQL 驱动，不替团队确定 ORM、统一迁移工具或服务拓扑。

## 2. 已知约束

1. 支持申请提交、多级审批、驳回和超时撤销；具体资格、层级、审批人及期限尚未确定。
2. 获批时段对应教室的全部座位不可接受个人预约；仅在 M1 确认占用后才能展示预约生效。
3. 需要回滚时，只撤销本申请对应的占用原因；不得覆盖个人预约、其他审批或维修造成的不可用状态。
4. 最终跨模块演示必须有独立运行实例之间的真实网络调用；实例划分由 ADR 批准。
5. 后端执行身份、操作权限和对象范围校验；前端隐藏按钮不构成授权。
6. M1 的整点小时和默认最多 4 小时约束不能直接推定为 M2 的申请时长政策；M2 时间规则另行确认。

## 3. 需求与拟验收标准

以下为拟验收标准；依赖未决政策的场景须先补充批准结论，不能由测试夹具暗中决定业务规则。

| 编号 | 需求 | 可观察验收标准 |
| --- | --- | --- |
| C-AUTH-01 | 登录与会话生命周期 | 合法演示账号取得有效会话；错误凭据不登录；退出、过期或撤销后不能继续操作；停用账号和权限变更的生效界限按批准契约验证 |
| C-AUTH-02 | 当前身份 | 返回服务端确认的用户标识、院系和授权信息；请求体或浏览器字段不能伪造身份；不暴露密码散列及会话秘密 |
| C-RBAC-01 | 操作与对象范围授权 | 每次请求都检查权限和管理范围；拒绝匿名、越权、跨范围及猜测他人标识的访问；读取与写入分别验收 |
| C-RBAC-02 | 公共权限接入 | A/B/D/E 按同一身份与授权契约接入；资源管理员、签到码展示端、运营及审计查询的范围明确，不默认授予全局管理权 |
| C-M2-01 | 申请提交与查询 | 合格用户提交教室、时段和用途，获得真实申请标识与状态；可查看本人申请；管理员仅查看授权范围；无效输入不生成申请 |
| C-M2-02 | 顺序多级审批 | 仅当前节点的获授权人员可处理；通过后进入下一节点；最后一级通过后进入占用确认流程；重复或并发操作只产生一次有效转换 |
| C-M2-03 | 驳回 | 按批准的意见和终态规则记录处理人、理由及状态；不允许后续节点继续处理；需要释放时进入可追踪补偿，不假定申请一定已有占用 |
| C-M2-04 | 超时撤销 | 在批准的截止时间与适用状态触发；无需浏览器在线；重启后可恢复扫描；重复执行不重复撤销、审计或发送业务事件 |
| C-M2-05 | 申请与审批追溯 | 保存提交时的审批流程快照、节点处理记录和状态历史；流程配置变化不静默改变在途申请；允许公开的字段由权限契约决定 |
| C-INT-01 | M1 原子占用 | M1 在最终写入时检查冲突；成功后该教室全部座位在对应时段不可个人预约；申请预检查成功不代表占用保证 |
| C-INT-02 | 超时与幂等恢复 | 相同操作重复发送不会重复占用；相同键不同内容被拒绝；响应丢失后通过结果查询或约定重试确认，不把未知当失败或成功 |
| C-INT-03 | 释放、乱序与多原因 | 只释放本申请来源；释放失败可恢复；撤销后的迟到占用请求不会重新生效；其他审批、个人预约或维修仍有效时不误恢复 |
| C-AUDIT-01 | 关键操作审计 | 登录结果、权限变更、申请、审批、驳回、超时及占用/释放有可关联记录；成功操作与本地审计原子提交，失败/拒绝事件不随业务回滚丢失 |
| C-AUDIT-02 | 审计可见性与隐私 | 审计查询单独授权，按范围过滤；不记录密码、令牌、签到码原文或完整敏感请求体；普通业务接口不能编辑或删除审计记录 |

## 4. 认证、权限与审计方案取舍

### 4.1 认证候选

首轮建议使用合成演示账号和服务端可撤销会话，预留统一身份提供者接入边界；不接入真实学校账号，不新增自助注册、找回密码或生产账号管理承诺。
服务端会话便于退出、账号停用和权限更新，但多个运行实例需要统一校验来源；JWT 可减少部分查询，但必须另定撤销与权限变更时效。
当前组件实现随机 Bearer 令牌对应的服务端可撤销会话，不实现 JWT 或刷新令牌；这不代表团队已批准全平台登录方案。

若选择 Cookie 会话，由 D/C 确认 HTTPS、HttpOnly、Secure、SameSite、CSRF、跨域和开发代理；若选择 Bearer 令牌，明确存储、过期、撤销及续期策略。
会话空闲/绝对期限、登录失败限流、账号初始化与密码散列依赖须在实现 Issue 中明确，不写入未经确认的数值。

### 4.2 授权候选

采用 RBAC 表达操作许可，并结合本人关系、院系、管理资源范围及当前审批节点判断对象权限。
“申请人”“当前节点审批人”“资源管理者”“审计查看者”是讨论中的能力分类，不代表已新增角色或默认授权。
账号角色分配须同时具备 auth.manage、已有权限和宿主显式管理范围策略；默认不开放。初始账号仅允许可信引导；自审等业务规则由 Workflow 明确传入，不提供生产默认值。

与 B 联合确认 B-OPEN-03：院系标识来源、资源元数据对外院系的可见性、管理范围、签到码展示权限和公开字段。
跨模块不得直接读写认证表作为接入方式；由公共能力的公开入口校验，独立运行实例的接入方式随服务 ADR 确认。

### 4.3 审计候选

本地成功业务操作与对应审计使用同一事务；跨实例调用不假装具备跨数据库事务。
跨实例审计仍是待实现方案：调用方持久保存待投递记录，接收方按事件标识去重；远程失败策略与保留期限待确认。本地成功操作当前明确采用审计失败即回滚。
失败和拒绝事件使用不会被业务回滚撤销的记录路径；不能在记录失败时返回“审计已成功”。
审计写入身份由可信认证上下文确定；普通客户端不能通过传入 actor 字段冒充他人。

主要风险是身份越权、审批滥权、错误超时撤销、网络未知结果造成双重操作，以及过度公开申请用途/审批意见。
由 C 与 F 记录实际风险及决定，必要时联系 A/B/D/E；不以“管理员”身份默认绕过公平性和数据范围。

由 C 检查内容，A 审查占用与补偿，B 审查资源引用与身份范围，D 审查页面/工程/拓扑，E 审查通知与维修，F 审查追踪和集成验收。
每项批准结论记录人员、日期、相关 Issue/PR 和适用版本；待决项未解决时只阻塞对应实现，不把文档合并当成批准全部政策。
