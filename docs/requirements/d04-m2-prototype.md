# M2 页面原型与接入边界

负责人 D（jiadongchen666），关联 [页面原型 Issue #13](https://github.com/ElastingYun/campus_resource_management/issues/13)、[接口对齐 Issue #10](https://github.com/ElastingYun/campus_resource_management/issues/10)。

## 原型范围

原型包含我的申请、检索、详情、新建申请和审批交互预览，使用显式标注的合成教室与申请，数据只存在页面内存中。首轮字段、审批流程、状态和时间规则仍需 C/B/A 确认，当前 UI view model 不作为服务端 API/schema。

入口为根页面的 M2 卡片，或 `/#m2-prototype`。`/#m2` 是未配置真实接口的工作台：显示未接入、禁用提交，不会在请求失败时偷偷使用合成数据。刷新或重新进入原型后重置示例记录。

## 数据来源与边界

M2Workspace 依赖 typed M2Gateway，业务数据通过 load/submit 进入页面；界面模型在 modules/m2-approval/models.ts，合成与未配置 gateway 在 gateways.ts。正式接口确认后另写适配器，将批准后的后端结构映射为页面模型，不直接要求后端采用原型字段。

prototype gateway 的 simulateDecision 仅用于审批视角演示，真实模式不会因此得到角色或审批权限。页面不能代替后端鉴权，也不会自行调用 M1 拼接审批事务。

表单只做基础必填、用途空白和结束晚于开始的交互检查。它没有套用 M1 的整点/4 小时规则，没有定义审批层数、院系准入、撤销或超时政策。正式规则批准后需补充服务端契约及对应页面验证。

## 验收场景

| 场景 | 预期 |
| --- | --- |
| 初始进入原型 | 标注合成数据和刷新重置；加载申请及教室 |
| 查询与详情 | 按教室/用途/编号过滤；无结果时不残留无关详情 |
| 表单基础校验 | 缺失信息或逆向时段不调用 submit，允许修正 |
| 演示提交 | 新示例出现在列表，仅表明原型操作完成 |
| 请求处理中重复提交 | 本页仅发起一次写操作，按钮保持忙碌 |
| 提交失败 | 保留输入，显示失败，不出现成功提示 |
| 真实接入未配置 | 明确不可用、没有假记录、不能提交 |
| 审批预览 | 明确只演示本页状态，不声称审批或座位占用生效 |

新增 Vitest、Vue Test Utils、jsdom 作为开发依赖，用于 DOM 和可观察交互测试，不改变运行技术栈。jsdom 版本需兼容现有 Node 22.16；Vitest 与现有 Vite 配合。实际锁定版本和测试结果以 package-lock.json 与 PR 为准。

运行：frontend 中 `npm ci`、`npm run test`、`npm run build`。前端 CI 加入行为测试；已有后端和容器检查仍保留。
