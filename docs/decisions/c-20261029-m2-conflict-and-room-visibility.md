# C-20261029：整室冲突与普通申请人教室范围

日期：2026-10-29。状态：**以下两项业务决策已获负责人在当前项目会话明确确认；技术契约、实现与非作者Review分别留证。** 负责人为当前用户/成员C（Git身份wuyihao）。关联 #23、#24、#40。

## 已批准规则

1. 负责人选择“拒绝整室占用，保留个人预约”：审批通过后，若最终占用与有效个人预约时段重叠，M1原子拒绝本次整室占用。既有个人预约保持，不自动取消或记违约；C保留审批事实，以占用冲突/effective=false表达未生效。
2. 负责人选择“已启用的校园级教室及本院系教室”：在已获申请权限的普通主体内，选择列表仅显示 enabled=true 且（access_scope=campus 或 access_scope=department且department_id匹配可信当前院系）的教室；提交时后端仍重新读取资源并校验。

campus教室允许department_id=null，null本身不是资格依据；必须同时有明确的campus标记。department教室必须有有效院系标识。浏览器提交的院系/角色和静态enabled不能证明动态时段可预约。

资格校验成功仅代表该次提交前读取到的主数据符合规则；最终占用仍由M1原子校验。资源变更对已有申请/预约的追溯行为、维修叠加、生产角色发放、审批层级/时间规则与人工重试继续按原待决事项处理。

## C配置兼容

C新增显式 `submission.room_access_policy="campus_or_own_department"`；该模式与 `allow_cross_department=true` 冲突并拒绝加载。它要求公开资源响应有access_scope，并支持campus的nullable院系。
既有配置未指定该字段时保留legacy行为，以兼容旧组件和合成夹具；新规则的验收/部署配置必须显式选择批准模式，不能把legacy配置的旧测试视为满足此决策。没有自动修改环境配置、授予角色或启用生产服务。

该决策没有替代A/B/D的代码Review，也没有确认未公开的普通查询路径、服务身份或整体拓扑。C不直接操作A/B私有表，真实外部验收保持在#23/#24。
