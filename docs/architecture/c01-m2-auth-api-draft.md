## 1. 所有权与运行边界

| 领域 | 提供者 | 可公开接入的能力 | 禁止的捷径 |
| --- | --- | --- | --- |
| 身份与权限 | C | 可信身份上下文、权限/范围判定、会话生命周期 | 信任浏览器传入的角色、院系或任意用户标识 |
| M2 | C | 申请、审批、历史、超时处理与集成结果 | 直接修改 M1 座位状态或 B 的资源表 |
| 资源 | B | 稳定教室/院系引用与批准公开的配置 | 以静态 enabled 推断动态可预约性 |
| 动态占用 | A | 原子占用、来源释放、执行结果查询 | 用 M2 的查询预检查替代 M1 最终并发校验 |
| 通知 | E | 发送及发送结果的公开契约 | C 自建另一套通知发送逻辑 |
| 审计 | C | 有授权的事件接收与查询 | 允许普通调用方冒充操作者、覆盖已有审计 |

代码可以处于同一仓库；进程、数据库、任务运行方式与身份验证位置由 D 组织 ADR。
最终 M2→M1 联调使用独立运行实例之间的网络契约，不把公共模块导入或进程内函数调用当作该链路的证据。
公共认证/审计的本地入口与跨实例接入方式分别评审，不默认增加独立认证服务或跨模块共享数据表。

## 2. 公共身份与授权候选契约

### 2.1 身份上下文

`Principal` 是可信服务端上下文候选，至少讨论以下内容：

| 字段 | 候选含义 | 约束 |
| --- | --- | --- |
| subject_id | 当前用户稳定标识 | 从有效认证结果取得，不能用请求体指定申请人 |
| department_id | 经确认的院系关联 | 标识与来源同 B 对齐，不信任客户端声明 |
| roles / permissions | 角色展示与操作许可 | 枚举及授予方式待定；前端展示不替代服务端校验 |
| data_scopes | 管理/查询的资源或院系范围 | 空、缺失及全局范围的含义必须明确，不能默认全权限 |
| session_ref / auth_version | 会话关联及失效判定信息 | 对外只返回获准公开字段，不暴露会话秘密 |

授权入口至少区分“是否登录”“是否可执行动作”“是否可操作该对象”；拒绝优先，不能靠猜不到标识防止越权。
当前身份查询仅供 UI 展示与交互，所有业务请求仍重新检查当前权限。
会话撤销、用户停用与角色调整的传播时限必须有精确验收界限，不能把令牌存在等同权限永久有效。

### 2.2 认证 API 候选

以下相对路径以 `/api/v1/auth` 为讨论前缀。当前组件使用用户名/密码和随机 Bearer 会话，统一身份提供者及全平台方式仍需 C-OPEN-01 决策。

| 方法与路径 | 意图 | 请求/响应边界 |
| --- | --- | --- |
| `POST /sessions` | 登录并建立会话 | 输入批准的凭据；失败不区分可用于枚举账号的内部细节；成功返回获准身份信息并交付会话 |
| `DELETE /sessions/current` | 退出当前会话 | 按可信会话定位并撤销；重复退出语义及 CSRF 约定待定；退出后旧会话不可再授权 |
| `GET /me` | 获取当前身份 | 返回获准公开的 Principal 投影，不返回密码散列、会话秘密或任意用户的授权详情 |
| `PUT /users/{id}/access` | 配置角色、范围及账号启停 | 需 auth.manage 和宿主显式账号管理策略；不允许授予自身没有的权限，默认关闭 |

首轮推荐合成账号与服务端可撤销会话，统一身份提供者作为后续适配；JWT/续期方案仅作为备选，未经决策不同时实现两套。
Cookie 模式需确定 HttpOnly、HTTPS 下 Secure、SameSite、CSRF、CORS 和代理；Bearer 模式需确定浏览器存储、撤销和续期。
会话过期、失败限流、密码散列及账号引导使用成熟依赖，具体包、版本与新增理由在实现计划中列明。
不提交真实账号、初始密码、生产密钥或 `.env`；演示账号的初始化方式与安全示例由 D/C 确认。

### 2.3 权限矩阵候选

下表是能力分类，不是已授予的角色。权限命名和真实角色映射由 C/B/D 与受影响成员批准。

| 能力 | 拟允许的行为 | 额外对象条件 |
| --- | --- | --- |
| 申请提交 | 创建本人申请 | 账号有效，满足申请资格及资源准入政策 |
| 本人申请查询 | 列表、详情、允许公开的历史 | 对象属于本人；不能通过筛选参数切换用户 |
| 节点审批 | 查看待办并通过/驳回 | 当前节点、对应资源范围、自审/替补政策均满足 |
| 运营查询 | 查询批准范围的申请 | 院系/资源范围和字段白名单，不能默认读取全校个人信息 |
| 资源管理 | 使用 B 的管理接口 | 管理范围由 B/C 对齐，不能推导出审批或审计查看权限 |
| 签到码展示 | 读取 A 的相应教室码 | 展示终端/角色和资源范围需 A/B/C 单独批准 |
| 审计查询 | 按批准条件读取审计 | 独立权限与数据范围，不随普通管理员角色自动获得 |
| 权限管理 | 授予/撤回角色 | 首轮是否开放管理 API、谁能授权及防提权规则待定 |

业务调用身份与服务调用身份分别验证。普通浏览器不能以 `source=M2` 或自填 actor 获得内部占用/审计权限。
服务如何证明调用方、如何传播用户上下文及区分系统超时操作者，由 ADR 和安全契约明确。

## 3. 审计候选契约

### 3.1 事件与访问

建议事件包含 `event_id`、操作者类别/标识、动作、目标类别/标识、发生时间、结果、必要的状态变化、`request_id` / 业务操作关联标识和事件结构版本。
系统超时任务明确记录为系统动作，保留相关申请与操作标识，不冒充原申请人。
服务接收端验证发送方身份、事件类型权限和上下文来源；不因调用方能联网就信任任意 actor 或结果。

- 本地业务成功与本地审计记录同一事务提交，避免只有状态没有审计。
- 跨实例调用方先持久化待发送事件；接收方按事件标识去重，同标识不同内容作为冲突处理。
- 失败/拒绝事件采用独立于被回滚业务事务的可靠记录路径，并受输入白名单和限流约束。
- 本地成功审计失败则回滚业务；远程投递、告警和人工处理策略须由 C-OPEN-08 决策，当前未实现远程审计投递。
- 无普通业务编辑/删除入口；保留期限、脱敏和归档由团队决定，不承诺数据库管理员无法篡改的审计能力。

网络接入与查询路径建议以 `/api/v1/audit` 为前缀：

| 方法与路径 | 意图 | 授权边界 |
| --- | --- | --- |
| `POST /events` | 可信服务提交审计事件（如 ADR 采用网络接入） | 仅授权服务；服务身份不等于任意用户身份；去重、持久化成功后才确认接收 |
| `GET /events` | 查询批准可见的审计 | 单独授权并过滤范围；筛选、分页与字段白名单待确认 |

当前未实现远程事件接收 API 或审计管理页面，仅提供本地事件写入及受权查询。采用本地接入时同样维护版本化事件结构，不绕过发送模块的数据所有权。

### 3.2 数据最小化

禁止记录密码、会话/刷新令牌、Authorization/Cookie 内容、签到码原文、完整请求体或真实学生私人资料。
申请用途、驳回意见只在批准的业务查询中按权限公开；审计按必要字段或脱敏摘要记录，长度、换行及日志注入输入需要验证。
请求关联标识不作为认证凭据；外部传入标识需校验格式，不允许通过日志注入制造伪审计。

## 4. 申请与多级审批候选契约

### 4.1 数据与快照

申请候选字段：稳定标识、服务端取得的申请人、教室标识、起止时刻、用途、审批状态、当前节点、版本及创建/更新时间。
提交请求不接受客户端指定审批结果、申请人、角色、任意审批流程或座位可用状态；未知/不允许字段的拒绝方式需在正式 schema 明确。
时区、时间区间、时长、跨日、申请提前量与截止时间由 C-OPEN-04 决策；校验起止关系不能替代资格及开放配置检查。

提交时保存经批准的流程版本与节点快照，包括顺序、候选审批资格/范围、适用的期限规则和必要配置来源。
第一版建议顺序审批，不额外承诺并行会签、任意流程编辑器或动态转签；人员离岗/替补、流程配置变化的处理须先决策。
审批节点保存处理人、决定、意见、处理时间及版本；历史只追加，不覆盖过去处理意见来伪造过程。

### 4.2 API 候选

以下以 `/api/v1/m2` 为讨论前缀；D 的前端消费真实状态，不从按钮点击推断业务成功。

| 方法与路径 | 意图 | 输入/响应要点 |
| --- | --- | --- |
| `POST /applications` | 提交申请 | 教室、起止时刻、用途及约定幂等信息；返回申请标识、审批状态、集成状态和版本；资格与资源引用由后端确认 |
| `GET /applications` | 授权申请列表 | 本人或经授权管理范围，由服务端确定；筛选/分页不能绕过对象范围 |
| `GET /applications/{id}` | 申请详情与公开进度 | 审批进度、获准意见、真实占用/补偿状态；不返回其他申请或秘密 |
| `GET /review-tasks` | 当前用户待办 | 只列当前节点且在授权范围内的任务；列表结果不代表后续操作必然获准 |
| `POST /applications/{id}/decisions` | 通过或驳回当前节点 | 决定、批准范围的意见、预期版本和幂等信息；节点与操作者由服务端确定，事务内重新校验 |
| `GET /applications/{id}/history` | 获准的处理历史 | 按权限返回追加记录；隐私字段与审计查询分开控制 |

不提供任意 PATCH 状态或角色的接口。当前提供 POST /applications/{id}/revocations，需 m2.revoke、资源范围、预期版本及流程快照中的 allow_revocation=true；不自动授予申请人撤回能力，也不支持重开终态。生产撤销规则仍须 C-OPEN-06 确认。
超时由后台可信任务处理，不暴露允许普通客户端填写任意“当前时间”触发撤销的端点。

### 4.3 两类状态及页面语义

当前分开保存审批决定与占用执行结果；以下枚举已用于代码，业务适用范围仍待评审：

| 维度 | 候选状态 | 语义 |
| --- | --- | --- |
| 审批 | `REVIEWING` | 当前节点待处理；中间节点通过仅推进节点 |
| 审批 | `PASSED` | 全部节点通过，不能单独解释为预约已生效 |
| 审批 | `REJECTED` / `TIMED_OUT` | 按批准政策驳回/超时关闭，不得继续普通节点审批 |
| 集成 | `NONE` | 尚无占用操作；不是可预约性结论 |
| 集成 | `APPLY_PENDING` / `APPLY_UNKNOWN` | 待发送占用或结果未知；页面显示处理中 |
| 集成 | `APPLIED` | M1 已确认该来源占用 |
| 集成 | `APPLY_CONFLICT` | M1 明确返回业务冲突；申请下一步去向待决策 |
| 集成 | `RELEASE_PENDING` / `RELEASE_UNKNOWN` | 已有释放意图，尚未确认完成 |
| 集成 | `RELEASED` | M1 已确认该来源已释放，不表示所有原因消失 |

“预约生效”至少要求审批通过、M1 占用已确认且无待执行的撤销意图；不能只看某一个字段。
获准的撤回/撤销操作须另有持久的生命周期意图与版本；这不篡改历史审批意见，也不能仅在内存写一个布尔值。
允许的状态组合和转换必须在正式契约列全；例如待审批不得直接标为 APPLIED，明确终态不能被迟到响应重新改为生效。

推荐默认仅在最后一级通过后申请占用；是否需要审批期间预占属于新增政策，未经批准不实现。
待审批超时和网络请求超时是两件事；占用确认或已生效申请是否受业务截止时间影响，由 C-OPEN-06 单独决定。

### 4.4 并发与超时执行

- 决定在同一数据库事务中校验身份、对象范围、当前节点、版本和截止条件；使用行锁或条件更新，不能先读状态后无条件写入。
- 同一节点并发通过/驳回、审批与超时竞争，只能有一个有效状态转换；另一方得到批准的冲突或幂等结果，不追加第二条成功审计。
- 最后一级通过的本地状态、成功审计、待占用操作记录一起持久化；HTTP 调用不占用长数据库事务，不假设网络和数据库可一起提交。
- 超时扫描使用可信服务端时间和持久截止时间；等号归属、时区及采用的时间来源经批准后精确断言。
- 任务具备重复领取/崩溃恢复策略。已处理状态、预期版本与稳定操作标识约束重复执行，不能仅靠单进程定时器防重。
- 领取租约、扫描频率、批量大小、重试间隔及通知投递方式与 D/E 对齐；不自行引入队列服务。

## 5. M2→M1 网络契约与恢复提案

### 5.1 待 A/C 共同确认的能力

下表不替 A 决定实际 API 路径、表、事务锁或时段冲突政策。

| 能力 | 候选内容 | 成功确认条件 |
| --- | --- | --- |
| 创建整教室占用 | 业务来源、申请标识、教室、时段、稳定操作标识、内容指纹/版本与追踪标识 | M1 原子确认冲突检查及来源占用写入，返回稳定引用/版本 |
| 查询执行结果 | 授权调用方及对应来源/操作标识 | 能区分已应用、明确拒绝、处理中及未确定；不可泄露他人结果 |
| 释放来源占用 | 原申请/占用引用、新的释放操作标识、版本与撤销原因 | 只移除该申请的原因；重复释放和先释放后创建的处理有明确定义 |

创建前的主数据/可用性查询只是提示；M1 必须在个人预约和整教室占用竞争的最终写入点保证一致性。
稳定标识究竟按申请、时段版本还是操作生成，由 C-OPEN-07 确认；释放是独立操作，不能复用创建的幂等键表示相反意图。
服务请求认证、超时上限、状态码和响应结构由版本化契约明确；内部占用端点不能让普通学生直接调用。

### 5.2 幂等与未知结果

建议幂等范围至少包含调用方、动作及操作标识，并绑定规范化请求内容。同键同内容返回一致业务结果，同键不同内容拒绝，不能覆盖旧记录。
幂等记录须持久化；保留期覆盖允许的查询、重试和恢复窗口，过期后的操作如何处理需决策，不能默认无限重试仍安全。
接口接受请求不等于已占用，明确完成后才记录 APPLIED；响应超时/断连按未知处理，不立即提交相反操作来猜测回滚。
未知操作通过结果查询或约定的同键重试收敛；查询“暂未找到”是否可作为未执行证据，必须覆盖仍在途的请求，不能据一次空结果生成新键。

### 5.3 持久操作记录与补偿

建议在 PostgreSQL 保存 M2 操作标识、申请/版本、动作、批准的负载、待执行/未知/完成状态、尝试次数、下次尝试及脱敏错误分类。
这是一种候选可靠投递记录，不批准新增独立消息系统。由 D 确认任务运行进程、领取租约与恢复；重试上限和人工处理入口须可追踪。

| 情况 | 拟处理边界 |
| --- | --- |
| 最后一级审批通过后进程退出 | 持久任务在恢复后继续，不能丢失占用意图 |
| M1 已占用但响应丢失 | 本地记为未知，以同一操作查询/重试；不能展示明确失败或制造第二笔占用 |
| M1 明确冲突 | 保存冲突结果；拒绝、改期或重新审批由 C-OPEN-05/07 选择，不自动取消个人预约 |
| 撤销与创建同时在途 | 持久化撤销意图，双方通过版本/终态防护或经批准的等价协议防止迟到创建复活；仅取消本地任务不够 |
| 释放失败或响应丢失 | 保留释放中/未知并恢复查询/重试；不能先显示已释放 |
| 其他审批/维修仍有效 | M1 只释放本来源，再按剩余原因判断；C 不把 RELEASED 映射为全室可预约 |

尤其需要验证“释放先到，旧创建后到”的乱序；A/C 可以选择终态记录或另一套有等价保障的协议，未确认前不得宣称补偿安全。
通知在批准的业务节点由 E 接入，通知发送失败与审批/占用失败分别记录；通知事件也需稳定标识和重复处理约定。

## 6. 候选持久化对象与迁移边界

| 范围 | 讨论中的对象 | 评审重点 |
| --- | --- | --- |
| 认证 | 用户、角色/权限关联、作用范围、会话 | 院系来源、撤权、会话失效、账号引导与最小权限 |
| M2 | 申请、流程/节点快照、审批决定、状态历史 | 引用标识、状态组合、不可变历史、版本与截止时间 |
| 集成 | 操作及通知/审计待投递记录（可按批准方案共用或分离） | 去重、领取/恢复、内容版本、重试与保留期限 |
| 审计 | 事件、授权查询所需索引 | 字段白名单、幂等、数据范围、保留与失败策略 |

当前 C 自有 SQL 实现上述对象；跨模块只保存稳定关联标识，不引用其他模块私有表，也不据此批准共享 schema。
原版本化 SQL 位于 m2_approval/migrations/，保持历史不变。统一 Alembic 的 0002_c_identity_approval 执行冻结基线，兼容已应用且校验一致的旧 C 数据库；已有空库、重复执行、旧数据保留与不一致拒绝测试。后续变更新增 revision；详见运行说明。

## 7. 错误与评审约束

候选错误语义：无有效身份 `401`，缺少许可 `403`，不存在或按批准策略隐藏 `404`，状态/版本/幂等内容冲突 `409`，输入不合法 `422`，登录请求限流 `429`。
状态码与机器错误码、可公开信息及重试建议由团队统一；不在错误里返回内部栈、SQL、秘密或他人资料。
对超时的写操作，响应或查询必须能表达“结果未知/处理中”；不能因 HTTP 失败就认定业务没有执行。

与统一工程绑定的事务、依赖注入、连接、密钥配置和 HTTP 客户端遵循 D 的标准。

需求追踪与未决项统一见[需求第 5 节](../requirements/c01-m2-auth-audit.md#5-待决策清单)；正式实现前记录批准版本及受影响 owner 的结论。
