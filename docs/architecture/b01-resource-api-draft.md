# B-01：资源主数据与 M1 接口边界草案

状态：**Draft / 待相关负责人评审，未批准、未实现。**

关联：[页面与资源需求](../requirements/b01-m1-ui-and-resources.md)、[验收与任务计划](../testing/b01-acceptance-plan.md)。
本文是 B 的讨论材料，不是可直接调用的 API 文档，也不批准数据库 schema、服务拓扑或权限策略。
路径、字段名、错误码和数据形状均为候选，需在实现任务开始前记录评审结论。

## 1. 数据与接口所有权

| 所有者 | 负责提供 | B 的使用边界 |
| --- | --- | --- |
| B：公共资源 | 教室、座位、开放时间、院系归属及静态启用配置 | 维护主数据及管理接口，不生成动态可预约结论 |
| A：M1 | 按时段搜索、预约、签到、历史、运营、动态可预约性及状态来源 | 页面读取真实结果；查询结果不能代替提交时的最终校验 |
| C：认证与审计 | 用户身份、角色、院系、数据范围和审计接入契约 | 后端执行授权，不信任浏览器传入的角色或院系作为凭据 |
| E：通知与 M3 | 通知能力、维修状态的业务来源 | B 不直接改工单表，不在浏览器触发违约任务 |
| D：工程 | API 前缀、客户端、服务发现、数据库连接与迁移约定 | 本文不先行创建框架或决定资源服务独立部署 |

M2/M3 通过批准的公开网络接口向 A 写回业务状态；B 不是这些写回的中转或裁决方。
资源主数据由 B 管理不代表 B 可独自改变 A/C/E 使用的资源模型；共享模型需受影响成员评审。

## 2. 候选字段与待决约束

下表中的“标识”是稳定的关联标识；采用整数、UUID 或其他格式，及其 JSON 表达方式由团队确认。
展示编号与内部关联标识分别讨论，避免修改教室名称或座位展示编号破坏已有业务引用。

| 对象 | 候选字段 | 用途与待确认约束 |
| --- | --- | --- |
| 教室 | `id`、`code`、`name`、`location` | 关联标识、管理编号、展示名称和位置；必填项、长度及编号唯一范围待确认 |
| 教室准入 | `access_scope`、`department_id` | 表达全校或院系限制；枚举、院系来源、跨院系管理员范围由 C 参与确认 |
| 教室配置 | `enabled` | 管理员维护的静态配置；创建默认值及修改生效策略待生命周期决策 |
| 座位 | `id`、`room_id`、`code` | 稳定关联、所属教室和唯一座位编号；编号规则、父教室有效性与变更规则待确认 |
| 座位属性 | `outlet_type`、`enabled` | 表达无插座、固定插座或导轨插座等候选属性及静态启用配置；最终枚举待评审 |
| 开放时间 | 教室关联、日期或周期、开始与结束时间 | 周期模板或具体日期方案待选择；时区、跨日、节假日、重叠与变更生效规则未定 |
| 追踪信息 | 创建/更新时间、版本标识 | 支持排查及防止并发编辑覆盖；字段、审计责任和乐观锁方案待确认 |

院系资源对非本院系用户是否显示元数据，由 C 确认；能看见教室不等于有权预约。
预约按整点小时计量是已知业务规则，不据此推定资源开放时间配置必须使用同一粒度。
静态启用、院系或开放时间的修改可能影响已有预约，必须先确定拒绝、延后生效或其他处理方案。
本草案不提供硬删除、级联删除、座位迁移教室或批量注销接口。

## 3. 资源接口候选清单

以下以 `/api/v1/resources` 为讨论前缀，最终前缀、版本、分页及返回封装与 D/A/C 对齐。
“查询”返回主数据；需要判断具体时段是否可预约时，调用 A 的搜索接口。

| 候选方法与路径 | 意图 | 输入/输出要点 | 依赖与限制 |
| --- | --- | --- | --- |
| `GET /rooms` | 查询教室主数据 | 候选条件：位置、院系；返回授权可见的教室列表 | 用户范围由后端结合 C 的身份判定；不是可预约教室列表 |
| `GET /rooms/{room_id}` | 查询教室详情 | 教室信息及批准公开的配置 | 不包含签到秘密、个人预约或工单详情 |
| `POST /rooms` | 新增教室 | 允许录入的字段；返回稳定标识和保存后的数据 | 仅获授权管理员；重复编号及无效院系需校验 |
| `PATCH /rooms/{room_id}` | 修改教室基本信息 | 仅更新明确允许编辑的字段 | 准入、启用及关联标识变更需另行确定规则 |
| `GET /rooms/{room_id}/seats` | 查询教室内座位主数据 | 候选条件：插座属性；返回座位与教室关联 | 不得将 `enabled` 当作实时可预约性 |
| `GET /seats/{seat_id}` | 查询座位详情 | 座位标识、教室关联和公开属性 | 失效引用、不可见与不存在的处理由 C/B 确认 |
| `POST /rooms/{room_id}/seats` | 新增座位 | 唯一编号、插座属性；返回已保存座位 | 校验父教室、编号及操作者管理范围 |
| `PATCH /seats/{seat_id}` | 修改座位基本信息 | 经批准的可编辑属性 | 不允许写动态状态、业务占用来源或未经决策的父教室变更 |
| `GET /rooms/{room_id}/opening-hours` | 读取开放配置 | 团队确认后的时间结构 | 提供给 A 使用，不能绕过其预约判断 |
| `PUT /rooms/{room_id}/opening-hours` | 更新开放配置 | 整份替换或其他语义待确认 | 配置校验、并发更新、已有预约影响和审计须先决策 |

生命周期操作（启用、停用、注销）单独评审后补充；普通更新接口不得暗中实现停用并取消预约。
创建时的静态配置默认值也需批准；UI 不发送未确认的 `enabled`、角色或动态状态字段。
批量录入、分页、排序、模糊查询、重复提交去重和更新版本校验均需评审，不视为已承诺能力。

## 4. M1 页面依赖 A/C 的能力

下列只列能力和数据需要，具体路由及 schema 由对应负责人提案，避免 B 单方面定下其他模块接口。

| 页面需求 | 需要的公开能力 | 关键输入/返回内容 |
| --- | --- | --- |
| B-UI-01 搜索 | A：按时段查询可预约座位 | 日期、开始/结束时间、资源及插座条件；授权结果、可预约性和可公开原因 |
| B-UI-02 预约 | A：预约提交与结果查询 | 座位、时段；预约标识、确认状态、冲突/资格错误；超时后查询和幂等策略待确认 |
| B-UI-03 签到 | A：签到提交、教室码展示 | 预约标识和输入编码；真实签到结果；展示码的读取权限、有效期与更新方式需 A/C 确认 |
| B-UI-04 历史 | A：本人预约历史与违约记录 | 允许公开的资源、时段和状态；再次预约重新走当前查询与提交 |
| B-UI-06 运营 | A：预约情况查询 | 经批准的筛选条件、指标和数据范围；统计口径及隐私字段由 A/C/B 确认 |
| 公共身份 | C：当前用户及授权信息 | 身份、院系和页面权限；资源后端仍独立校验每次请求 |
| 时长配置 | A/D：已确定归属的业务配置读取 | 当前最大预约时长及必要时间信息；前端不把默认 4 小时写成不可变业务规则 |

提醒与超时任务归 A/E；B 按接口查询状态，即使学生关闭页面，后端任务仍须按批准规则运行。
教室码每天更新来自课程任务书附件 1；轮换时区、宽限期及旧码处理仍需 A 明确。

## 5. 静态配置与动态状态的边界

- `enabled` 是资源主数据候选字段；`availability` 是 A 对具体用户、时段和业务状态计算的概念。
- `enabled=true` 不能证明可预约；开放时间、院系资格、M1 预约、M2 占用和 M3 维修仍可能阻止预约。
- B 的资源写接口不接受动态 `availability`、预约状态或占用来源字段；A 保留来源类别及关联业务信息。
- 启用资源不解除审批或维修限制；单张工单验收或一次审批撤销也不能无条件恢复座位。
- 查询与预约提交之间可能发生变化，由 A 在提交时重新校验并处理竞争，B 展示真实结果。
- B 不删除已有业务记录以便停用/注销成功，不读取其他模块的内部表拼接可预约性。

## 6. 错误、权限、审计与隐私提案

| 情况 | 候选处理 | 待确认 |
| --- | --- | --- |
| 无有效身份、权限不足 | `401`、`403` | C 的登录/令牌方式、过期处理、数据范围及错误封装 |
| 资源不存在或不可见 | `404` 或团队批准的隐藏策略 | 是否向无权限用户区分两种情况，避免泄露资源信息 |
| 输入格式、引用或业务约束不合法 | `422` 或批准的校验错误 | 字段级错误、长度、院系校验和前后端统一提示 |
| 重复编号、版本冲突或受业务引用限制 | `409` 或批准的冲突错误 | 唯一范围、并发策略、生命周期规则与可重试条件 |
| 超时、网络或服务失败 | 显示失败或结果未知，允许按契约恢复 | 不能把写请求超时等同于未写入；查询/重试方式由接口约定 |

状态码仅作讨论建议，不推翻 FastAPI、认证或共享 API 的后续约定。
审计建议覆盖操作者、目标资源、动作、结果和必要追踪标识；事件格式、失败策略和接入由 C/B 确认。
不记录认证凭据、教室签到码原文或真实学生私人资料；演示和测试使用合成数据。
资源管理与预约公平性、错误停用及记录可见范围有关，相关决策和实际问题需保留给 F 汇总。
