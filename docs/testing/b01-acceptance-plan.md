## 1. 范围、依赖与验收方式

- B 负责 M1 页面、教室/座位主数据接口及对应测试；A 负责可预约性、预约、签到和状态计算。
- 认证、角色、院系信息和审计接入依赖 C；工程、数据库及迁移约定依赖 D。
- 通知任务由 A 与 E 协作；M2/M3 联调由相关成员参与，F 组织集成验收。
- 使用合成用户、院系、教室、座位及预约数据，禁止把真实学生资料作为测试夹具提交。
- 下列“预期”描述目标行为；未确认的业务政策先记录决策，再补充精确断言。
- 资源接口使用公开 API 验收，页面检查用户可观察行为；不直接修改数据库伪造业务链路。

## 2. 页面行为验收矩阵

| 需求 | 正常路径 | 失败与边界 | 责任与依赖 |
| --- | --- | --- | --- |
| B-UI-01 搜索 | 选择日期、整点时段、教室和插座条件，展示符合条件的结果 | 无结果有空态；查询失败可重试；未知或缺失可用性不显示为可预约；切换条件后不得让旧响应覆盖新结果 | B 展示，A 返回可预约结果；院系检查依赖 C |
| B-UI-02 预约 | 选择座位并提交时段，成功后显示后端确认的预约记录 | 同座位竞争、重复点击、权限拒绝和请求失败均有明确反馈；失败不显示成功 | B 交互，A 执行预约和幂等/冲突检查 |
| B-UI-03 签到及码展示 | 展示预约签到入口，提交正确教室码后显示后端确认的已签到状态；授权展示端展示该教室当日编码或二维码 | 错误教室、过期码、无资格、超时和重复签到按后端结果展示；失败不自行变更状态 | 编码生成、有效性和签到判断归 A；展示权限与 C 确认 |
| B-UI-04 历史及再预约 | 查看本人历史与状态；从历史带入座位后重新查询并确认时段 | 不暴露他人记录；原座位停用、占用或权限变化时反馈当前不可用原因 | A 提供历史及重新校验，B 不复制历史预约直接作为新成功记录 |
| B-UI-05 资源管理 | 授权管理员新增/编辑教室与座位，并查看保存结果 | 必填缺失、重复编号、无权限、失效引用和提交失败有反馈；失败保留可修正输入 | B 实现，C 提供后端授权边界 |
| B-UI-06 运营查看 | 授权用户按批准的筛选条件查看预约情况 | 加载、空数据、接口错误、无权查看均可辨认；不得展示超出角色范围的个人信息 | A 提供统计/查询，C 确认范围和隐私字段 |

所有页面补充键盘可操作、表单标签、加载反馈及错误文案检查；具体组件测试工具随 D 的脚手架确定。
预约和资源保存请求发生超时且结果未知时，不直接提示“未提交”；后续查询/重试方式按批准的幂等契约验证。

## 3. 资源接口验收矩阵

| 需求 | 正常路径 | 失败与边界 | 待确认项 |
| --- | --- | --- | --- |
| B-RES-01 教室数据 | 创建并查询教室，修改允许编辑的名称、位置、院系等字段 | 缺失/超长/空白输入被拒绝；未知院系和不存在的教室被明确处理 | 编码唯一范围、字段长度、院系标识来源 |
| B-RES-02 座位数据 | 在已有教室新增座位，维护插座属性并按条件查询 | 不存在的教室不可挂接；同一编号的重复提交按契约处理；跨教室数据不串用 | 座位编号唯一范围、批量录入范围 |
| B-RES-03 开放时间 | B 保存并返回合法开放配置；与 A 联调验证预约候选遵守该配置 | 格式错误和起止颠倒被拒绝；非整点、跨日及重叠配置按批准策略处理 | 周期模板、时间粒度、节假日、跨日规则、时区、变更生效策略 |
| B-RES-04 权限范围 | 全校/指定院系开放规则按批准策略限制查询与操作 | 学生直接调用管理 API、伪造院系、跨院系越权均被后端拒绝 | 管理角色范围、院系归属校验和错误响应格式 |
| B-RES-05 静态启用与生命周期 | 按批准策略维护静态启用配置，保留可追溯标识；启用不覆盖动态占用 | 已生效的父教室停用限制不能被座位查询或预约绕过；既有预约不能被静默删除 | 停用对既有预约的处理、生效时间、恢复流程、删除是否允许 |
| B-RES-06 权限与失败反馈 | 授权管理员操作成功，按 C 的契约记录必要审计 | 匿名、普通学生和越权管理员直接调写 API 被拒绝；失败不显示保存成功；审计不泄露凭据或签到码 | 管理数据范围、审计格式、审计失败处理和错误封装 |
| B-RES-07 迁移与初始化 | 在统一工程中从空库重放迁移；执行合成种子脚本两次后资源数及标识不重复 | 无效初始化数据不生成失效关联；失败可排查；不混入真实学生资料 | D 的迁移工具、执行方式、种子数据维护及事务约定 |

前端隐藏按钮只改善交互，不能作为权限测试通过的证据；资源 API 必须独立验证授权。
静态 `enabled` 仅表示主数据启用状态，动态可预约性由 A 汇总时段、资格、预约、审批和维修状态后返回。
停用/启用的 API、迁移和审计方案确认后再实施；不得通过删除历史关联记录解决引用问题。

## 4. 跨模块及时间边界场景

| 场景 | 验收预期 | 执行边界 |
| --- | --- | --- |
| 时段长度 | 在开放、身份合格且无冲突等前置条件满足时验证时长：整点小时、默认 4 小时满足时长限制、超过 4 小时被拒绝；修改配置后按新上限判断 | A 校验规则，B 展示配置及拒绝原因；无效输入须直接调用后端验证 |
| 相邻与重叠时段 | 两个区间相邻、部分重叠、完全包含及同起止分别按批准的区间语义处理 | A 确认并实现，B 校验页面反映同一结论 |
| M2 整教室占用 | 审批通过后对应时段全部座位不可预约，页面刷新后呈现服务端结果 | 使用 M2→M1 公开网络接口，由 C/A 配合；已有预约冲突策略待决策 |
| M3 维修下架 | 有“维修中”工单时教室全部座位不可预约；仅验收通过按规则恢复 | 使用 M3→M1 公开网络接口，由 E/A 配合；B 不把工单完工等同恢复 |
| 多原因叠加 | 两张维修工单仅一张验收，或审批占用仍有效时，座位不被无条件恢复 | A 汇总有效来源；B 不在浏览器推算或覆盖状态 |
| 查询后抢座 | 查询显示可用后被他人占用，再提交时提示冲突并更新当前状态 | A 保证一致性；B 不把查询快照视为预约保证 |
| 每日教室码 | 新旧日期、不同教室编码及授权展示均符合批准的有效期规则 | A 生成和验证，B 展示；换日时区和刷新方式待确认 |
| 提醒与违约 | 预约前 15 分钟、开始后 10 分钟未签到提醒；15 分钟未签到取消、释放并记违约 | A/E 后台执行，B 查询展示；无需保持页面打开也应触发 |
| 临界点与重试 | 签到与超时任务竞态、网络重试不重复违约/通知；时间边界依据批准规则断言 | A/E 测试后端任务，B 验证最终状态和反馈；边界含等号策略待确认 |

跨模块联调须覆盖接口失败、重复投递与恢复后重新查询；补偿策略未经确认不推测预期。
最终课程演示需要独立运行服务间真实网络调用，进程内函数调用或前端 Mock 不构成该证据。
