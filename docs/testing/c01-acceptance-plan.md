## 2. 身份、权限和审计验收矩阵

| 用例 | 追踪需求 | 正常路径 | 失败与边界断言 |
| --- | --- | --- | --- |
| C-T-01 | C-AUTH-01 | 合成账号登录、取得会话并访问授权 API；退出后失效 | 错误凭据、会话过期/撤销、账号禁用；按批准的限流和撤权传播界限验证，不打印秘密 |
| C-T-02 | C-AUTH-02 | 当前身份返回服务端确认的用户、院系及允许公开授权信息 | 伪造申请人/角色/院系、修改会话内容不能改变身份；响应无密码散列和会话秘密 |
| C-T-03 | C-RBAC-01 | 本人查看申请，当前节点且有范围的审批人操作成功 | 匿名、缺少权限、跨院系/资源、猜测他人标识；同时验证列表、详情与写接口，不只检查按钮隐藏 |
| C-T-04 | C-RBAC-02 | A/B/D/E 通过批准的公共认证入口取得一致身份判定 | 普通资源管理权不能自动变成审批/审计权；签到码展示按 A/B/C 规则；服务请求和用户请求不能冒用彼此身份 |
| C-T-05 | C-AUDIT-01 | 成功状态和对应审计一起提交，能关联申请/操作/请求 | 注入本地审计写入失败验证批准的事务策略；业务失败或授权拒绝仍有可靠记录；跨实例重投不重复记事件 |
| C-T-06 | C-AUDIT-02 | 授权人员只查询范围内批准字段 | 未授权查询、伪造 actor、同事件标识不同内容、超长/日志注入输入被处理；秘密与敏感原文不进入响应或日志 |

C-T-01 额外覆盖并发退出/使用、重启后的撤销状态、会话空闲与绝对期限临界点；具体等号归属随正式契约确认。
C-T-05 区分“重试尝试日志”与“成功业务审计”：可以记录多次尝试，但同一成功状态转换不能被重复算成多次业务成功。

## 3. 申请、审批和超时验收矩阵

| 用例 | 追踪需求 | 正常路径 | 失败与边界断言 |
| --- | --- | --- | --- |
| C-T-07 | C-M2-01 | 合格申请人提交有效教室/时段/用途并读取本人进度 | 无资格、无效教室、格式错误、起止倒置、越权查询、不允许字段被拒绝；时间粒度/时长/跨日按 M2 决策断言 |
| C-T-08 | C-M2-02 | 使用批准流程完成中间节点和最后节点；最后节点后只进入占用待确认 | 跳级、过期版本、非当前审批人、超范围、自审/替补按批准规则处理；不能由客户端指定成功状态 |
| C-T-09 | C-M2-02 | 两个独立事务并发操作同一节点，只有一个转换成功 | 同时通过/驳回、双通过、重复幂等键；获胜节点/审计/待执行操作只生成一次，相同键不同内容不覆盖 |
| C-T-10 | C-M2-03 | 当前节点驳回并保存批准要求的意见与处理人 | 驳回后不能继续普通审批；已无占用不伪造释放；需补偿时不得提前显示已释放 |
| C-T-11 | C-M2-04 | 推进可信时钟至批准截止条件，后台关闭适用状态的申请 | 截止前、等于、后；审批与超时竞态；跨日/时区；任务重跑和进程重启不重复状态转换/成功审计/业务事件 |
| C-T-12 | C-M2-05 | 查询到流程快照、节点决定和授权历史 | 配置更新不改变在途流程；他人意见与用途按字段白名单过滤；不允许覆盖旧决定伪造历史 |

C-T-09 使用真实 PostgreSQL 事务屏障制造竞争，不能仅串行发两次请求后宣称并发安全。
C-T-11 区分审批截止时间、HTTP 超时、任务领取租约以及业务时段结束；这些时间不能共用一个未经确认的“过期”条件。
“已生效后自动撤销”不作为已确认要求；如批准该政策，再补充在途创建/释放、迟到响应和通知断言。

| 用例 | 追踪需求 | 执行与可观察结果 | 证据/依赖 |

| C-T-15 | C-INT-02 | M1 完成写入后丢弃响应；M2 展示未知/处理中；查询或同键重试收敛为一个真实结果 | 故障注入只作用于网络边界；同键不同内容拒绝；查询暂未找到不自动生成新操作 |
| C-T-16 | C-INT-02 | 在本地提交后发送前、发送后回写前分别终止任务进程，再恢复 | 持久操作不丢失；重复领取/租约过期不会造成重复占用；重试上限及人工待处理按契约验证 |
| C-T-17 | C-INT-03 | 创建在途时发起获准撤销，让释放先到、旧创建后到；再投递迟到响应 | 终态/版本协议防止占用复活；本地不会被旧响应改回生效；需 A 的真实实现 |
| C-T-18 | C-INT-03 | 释放响应丢失/服务失败后重启恢复；重复释放同一来源 | 未确认前保持释放中/未知；完成后仅撤销该申请原因，其他审批/个人预约/维修仍阻止相应预约 |
| C-T-19 | C-M2-04、C-AUDIT-01 | 超时/审批结果经批准通知契约投递，响应丢失后恢复 | 通知失败与业务失败分开；重复投递不制造第二次业务事件，E 验证实际发送行为 |
| C-T-20 | C-AUTH-01、C-M2-01、C-AUDIT-01 | 从空 PostgreSQL 库按顺序执行统一迁移，再重复执行合成种子初始化 | 所需表/索引可用，种子不重复，无真实资料；统一 Alembic、旧 C 基线接入与初始化命令见运行说明 |

个人预约冲突已批准“拒绝整室占用，保留个人预约”，C-T-14 应按[2026-10-29 决策](../decisions/c-20261029-m2-conflict-and-room-visibility.md)验证；维修叠加仍未批准。C-T-18 仍须验证仅释放本来源，不能通过删掉已有预约或维修原因让用例通过。
集成验收同时证明“有网络请求”和“请求后的可观察业务变化”；只有 HTTP 200、日志行、进程内调用或前端 Mock 均不足以证明。
